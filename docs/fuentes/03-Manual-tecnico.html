2. Configuración inicial

Solo en una instalación nueva, copie backend/.env.example a backend/.env y frontend/.env.example a frontend/.env. No sobrescriba los archivos de una instalación existente. Complete DB_URI con la autenticación de su MongoDB local y mantenga DB_DATABASE=libreria_san_francisco para el sistema habitual. Las claves reales no se guardan en Git.

cd backend
php artisan key:generate
php artisan libreria:jwt-clave
php artisan config:clear
cd ..
docker compose up -d --wait

El contenedor local se llama mongodb_libreria y expone MongoDB en el puerto 27018. Los scripts docker/mongo/iniciar.sh y salud.sh preparan el replica set rs0 y su autenticación interna. Espere un estado saludable. Un MongoDB standalone no permite las transacciones necesarias para las operaciones.

Índices

El docker-compose.yml local no debe exponerse directamente a Internet. La publicación requiere credenciales nuevas y reglas de red propias; no reutilice accesos locales.

4. Sesiones y seguridad

El access token JWT dura 15 minutos por defecto y permanece en memoria del navegador. La renovación usa una cookie HttpOnly rotativa con límite absoluto de siete días. No se guardan JWT ni PIN en localStorage o sessionStorage. Cerrar sesión revoca la sesión y limpia el estado de la interfaz.

ControlImplementación
AutenticaciónFirma, propósito, emisor, audiencia, fechas y sesión activa.
AutorizaciónMiddleware modulo; denegación predeterminada. Usuarios exclusivo del superusuario.
RenovaciónCookie libreria_refresh; ruta /api/auth; SameSite=Lax; Secure en producción.
SucursalesPOST /api/auth/sucursal; X-Sucursal-Id evita escrituras en contexto obsoleto.
Contraseñas y códigoHashes; el código no se devuelve en listados ni se envía a las APIs externas.
Cambios de accesoCambiar asignaciones y permisos revoca sesiones según las reglas del servicio.

En publicación conviene servir la interfaz y /api bajo el mismo origen HTTPS. No basta permitir CORS entre dos dominios ajenos: la cookie SameSite debe poder renovarse correctamente. APP_DEBUG=false y JWT_COOKIE_SECURE=true son obligatorios en ese entorno.

Responsable de las tres integraciones: José Alfredo Davila Abrego. Las APIs simuladas se ejecutan en procesos HTTP distintos del backend principal y se consultan realmente. Banguat es el servicio público real; los otros dos son proveedores académicos de prueba permitidos por el enunciado.

ProveedorContrato y tratamiento
BanguatSOAP 1.1 TipoCambioDia sobre HTTPS; fecha/referencia verificadas, XML sin entidades externas y caché de 30 minutos.

cd backend
php artisan libreria:apis-demo --no-interaction
cd ..
node docker/apis/iniciar.mjs

Conserve el archivo privado de configuración y el historial JSON de ambos proveedores. Su clave de idempotencia permite recuperar el mismo comprobante tras reiniciar con ese historial. Se rechaza una clave usada con otro contenido. No hay reintentos automáticos de los POST. La respuesta se valida antes de guardarla en el ERP.

Si Windows confía en Banguat pero PHP informa un error de CA, configure un PEM apropiado siguiendo la sección HTTPS de Banguat del README. Nunca desactive la comprobación TLS. El servidor público debe usar su propio almacén de CA, no el archivo privado de esta máquina.

Use sus opciones --help y las instrucciones de .ia/TESTING.md. No apunte pruebas destructivas a la base real ni cambie sus guardas de nombre/entorno.

Respaldo y recuperación

  • Antes de migrar o trasladar datos, cree un mongodump autenticado en una ubicación privada.
  • Conserve el archivo junto con la fecha y el nombre de base; no lo agregue a Git.
  • Restaure primero en otra base o entorno y compruebe saldos, documentos y kardex.
  • Almacene los secretos y el historial de las APIs simuladas con respaldo propio.
  • No use docker compose down -v para resolver un fallo: elimina los volúmenes de datos.

El contenedor puede ejecutar mongodump/mongorestore con las variables de autenticación internas, sin escribir claves literales en la línea de comandos. Los comandos concretos de copia y restauración están en database/RESPALDO.md y deben adaptarse a la base de destino.
