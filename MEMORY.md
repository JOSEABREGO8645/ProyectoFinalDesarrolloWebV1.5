# Memoria del proyecto — Librería San Francisco
(Solo decisiones, archivos y pruebas verificadas.)

## Decisiones
- Stack 3: MongoDB 8.2 (Docker, puerto 27018) + Laravel + Vue 3 / Vite / Axios.
- Arquitectura backend: Model → Repository → Service → Controller + FormRequest.
- Referencias entre colecciones como STRING con el _id del documento.
- Sin Vue Router: navegación por hash en App.vue.

## Avance: fases 8 y 9
- Autenticación implementada con firebase/php-jwt 7.2.1. Access JWT HS256 de 15 minutos, validando algoritmo, firma, emisor, audiencia, propósito y expiración. Refresh opaco de 7 días absolutos, rotado mediante actualización condicional en MongoDB y guardado únicamente como hash en auth_sessions. Reutilizar el refresh inmediatamente anterior revoca la sesión. Logout revoca tanto access como refresh.
- El navegador mantiene el access token en memoria y el refresh en una cookie HttpOnly, SameSite=Lax, ruta /api/auth y Secure en producción. Axios recupera la sesión al recargar y comparte la renovación entre solicitudes concurrentes; utiliza Web Locks cuando están disponibles para coordinar renovaciones entre pestañas. No se guardan tokens ni contraseñas en localStorage/sessionStorage.
- Sesion y Usuario fijan auth_sessions y usuarios como sus colecciones. Usuario tiene índice único en usuario y usa Hash de Laravel para contraseña y código de facturación. No se utiliza la colección users ni autenticación relacional. Los cambios de contraseña, rol, sucursal, estado o módulos incrementan atómicamente la versión de seguridad del usuario e invalidan sesiones anteriores, incluso si no se hubieran marcado como revocadas.
- Usuarios tiene Model, Repository, Service, Controller, FormRequest, servicio Axios, View, Table y Form propios. Permite crear, consultar, buscar, filtrar, editar, asignar sucursal/rol/módulos y eliminar cuando no hay historial. Al editar, contraseña/código vacíos conservan los hashes; omitir estado/módulos conserva los valores actuales. Se impide al superusuario eliminarse, desactivarse o quitarse su rol. Una sucursal con usuarios activos no se puede desactivar sin reasignarlos o desactivarlos primero.
- Roles del kit: superusuario con todos los módulos conocidos y administración de Usuarios; empleado con acceso completo al CRUD solo de los módulos asignados. AutenticarJwt y middleware modulo protegen todas las rutas de negocio; se deniega por defecto, incluso para módulos desconocidos. 401 identifica falta de sesión y 403 falta de permiso. No hay registro público.
- Referencias mínimas para formularios en /catalogos/sucursales y /catalogos/proveedores, con permisos propios. El empleado solo consulta existencias de su sucursal; solicitar otra sucursal devuelve 403. Los filtros y selectores del Catálogo se adaptan al perfil.
- OrigenSesion exige X-Requested-With y verifica Origin en login/refresh/logout. FRONTEND_ORIGINS configura la lista exacta compartida por CORS; no se permiten comodines. Login limita a 5 intentos por usuario/IP y 30 por IP por minuto; código de facturación a 5 por usuario/IP. Mensajes de login genéricos para cuentas inexistentes, incorrectas o inactivas.
- Vite usa /api con proxy hacia VITE_API_PROXY_TARGET; frontend/.env y los ejemplos se actualizaron. Se generó JWT_SECRET aleatoria en backend/.env sin exponerla. libreria:jwt-clave permite configurar una clave si falta, conservando las ya configuradas.
- Acceso inicial real creado mediante libreria:crear-admin --generar-clave: usuario admin, contraseña aleatoria en backend/storage/app/private/acceso-inicial.txt. Se verificó que ese archivo y ambos .env están ignorados por Git. No se alteraron otras cuentas ni catálogos existentes. El comando también permite --crear-sucursal de forma explícita para instalaciones vacías.
- Verificación en el backend local del proyecto: login 200, perfil 200, consulta de Catálogo 200, logout 200 y rechazo posterior del mismo access token con 401. La contraseña inicial y los tokens se consumieron localmente sin mostrarlos en la salida.
- Verificación técnica: route:list --path=api muestra 39 rutas y route:list -v confirma autenticación/módulo en las rutas protegidas. Suite completa: 96 pruebas, 543 comprobaciones, todas aprobadas. Incluye expiración, renovación, cookies, origen, limitación, revocación, permisos, escalada de privilegios, sucursal, CRUD de Usuarios y regresión de catálogos. Pint y npm run build correctos; composer audit no reportó avisos de vulnerabilidad.
- Postman actualizado y ejecutado con Newman: auth.postman_collection.json (31 solicitudes, 35 comprobaciones) y catalogos.postman_collection.json (26 solicitudes, 28 comprobaciones), sin fallos. Los casos sin token y sin permiso están comprobados. Los reportes están en frontend/test-results/ (ignorado).
- Edge/CDP: auth.browser.mjs y catalogos.browser.mjs pasaron con cuentas ficticias de una base aislada. Se comprobó login, recuperación al recargar, renovación concurrente única, cookie HttpOnly, ausencia de tokens en Web Storage, logout, navegación por hash protegida, perfil empleado, CRUD de Usuarios, duplicados/inactividad, escritorio/móvil y regresión de los catálogos. Capturas en test-results/; el perfil de pruebas se cerró.
- frontend/tests/run-browser.py prepara BD/caché temporales, inicia servidores propios en 8002/5175, ejecuta navegador o Newman, detiene sus procesos y elimina exclusivamente su BD de pruebas. Los fixtures no modifican la base del proyecto. README, .ia/SECURITY.md y database/COLECCIONES_MONGODB.md documentan los contratos actuales.
